## Status update rules

1. Change `NOT RUN` to `PASS` only when happy, negative, permission, console, network, persistence, and applicable responsive checks have evidence.
2. Use `FAIL` when observed behavior differs from the expected result; add a stable bug ID immediately.
3. Use `BLOCKED` only when the named account, data, provider, device, environment, or authorization is unavailable; state the exact dependency in Notes.
4. Use `NOT APPLICABLE` only per test dimension, never to avoid a relevant role or negative case.
5. After a fix, retain the bug ID and attach regression plus journey-retest evidence before returning to PASS.
